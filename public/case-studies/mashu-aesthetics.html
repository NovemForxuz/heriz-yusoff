The brief

A clinic that doesn't exist, built like one that does

Mashu Aesthetics was a coursework client brief: design and build a site for a fictional aesthetic clinic offering face and body treatments in Singapore, with a stated objective to lift enquiries by 20% within three months. Four of us split the build across branches — services, promotions, testimonials, and the pages below — and merged into main through pull requests. The site still runs today on GitHub Pages.

Feature deep-dive

The service picker, from event to render

The homepage's "Customised Services" block is the one interactive moment on an otherwise static marketing site. Vanilla JS reads which tab was clicked, then two independent view-models — the tab state and the visible panel — get toggled off matching CSS classes. No framework, no state library: just enough logic for a static Bootstrap page to feel alive.

js/ui.js
function toggleService(evt) { const getClass = {'For Men': 'for-men', 'For Women': 'for-ladies'} const buttons = document.querySelectorAll('.services-div .col-6') let currentOpt = '' buttons.forEach((btn) => { // mark the clicked tab active, clear the rest if(btn.innerText === evt.target.innerText) { btn.classList.add('active') currentOpt = btn.innerText } else { btn.classList.remove('active') } }) const imgDiv = document.querySelectorAll('.services-div .img-outer-div') imgDiv.forEach((div) => { // show only the panel matching the active tab div.style.display = div.classList.contains(getClass[currentOpt]) ? "block" : "none" }) }

The tab click is only half of it. Each gender also carries a six-item desc-content-div carousel — a jQuery click handler on the dots swaps the treatment title, blurb and link, one gender-specific content set at a time. You clicked through it in the demo above; here's the handler behind it:

js/ui.js
$('.for-ladies .dot').click(function () { let dotNum = '' $('.for-ladies .dot').children().hide() $(this).children().show() dotNum = this.classList[1] // swap in the matching description panel $('.for-ladies .desc-content-div').hide() $(`.for-ladies .desc-content-div.${dotNum}`).show() });

Six of these ship per gender, each pointing at a different concern — milia, dark circles, pigmentation, sensitive skin, acne, ageing — and a "Learn More" link into the matching treatment page. Duplicated for .for-men with its own content, which is the kind of copy-paste I'd reach for a shared component to fix today.

Beyond features

Keeping main shippable

Branch integration

I merged two of my own feature branches (heriz-membership, heriz-interactive-serv) into main, plus one teammate's. When a merge left main broken on the 14th, I traced it and fixed it the same day.

SEO & accessibility

A dedicated pass added <meta name="description"> to 9 pages and alt-text plus title attributes to every content image — unglamorous work, but the brief's whole premise was more enquiries, and search snippets and screen readers are how strangers find a clinic they've never heard of.

The unglamorous half of the job — untangling a broken merge, writing alt text for forty images — is what actually keeps a team's site shippable.

Reflection

What I'd build next

Given more time, the next thing I'd own is turning that membership sign-up form into something that actually posts somewhere — right now, like the rest of the site, it's frontend-only. I'd also revisit the service picker's dot-by-dot carousel: it works, but updating its content today means hand-editing three places at once, which is exactly the kind of thing I'd rather refactor than repeat.
