Overview

CareRoute AI is a six-worker triage pipeline: a patient's free-text symptoms are normalised, classified into an acuity code by a trained severity model, checked against a deterministic red-flag override, routed to a care tier and clinic, then passed through my Human-in-the-Loop gate and a final Reflection critic — each step streamed to the frontend over SSE and passed agent-to-agent on a typed message bus. My component sits second-to-last: by the time a case reaches HITL, every upstream worker has already produced an opinion, and HITL's job is to decide whether a machine's opinion is good enough to act on without a clinician looking at it first.

Problem

The system's own design principle is "AI assists, clinician decides" — but nothing enforces that unless one component is explicitly responsible for catching the cases where the AI shouldn't decide alone. Skip HITL and two failure modes go unchecked: a confident-but-wrong acuity call reaches the patient with no human check, or a returning patient whose symptoms are trending worse across visits gets treated as a fresh, independent case. HITL is the last gate before a case is handled without a clinician in the loop, which is also why it's the one component our advisor singled out for scrutiny — see Decision 1.

Your contribution

Owned the Human-in-the-Loop (HITL) agent (hitl.py) — the checkpoint responsible for surfacing cases that require clinician review before a triage decision is finalized — plus the downstream Clinician-Handoff agent (handoff.py) that turns an escalation into a reviewable packet for the clinician queue.

  • Designed the escalation policy itself: an any-of composition over three independent floors (deterministic safety-override trigger, classifier confidence below threshold, cross-visit recurrence at equal-or-worse acuity), with reasons accumulated rather than short-circuited so a clinician opening the queue sees every signal that fired, not just the first one.
  • Declared HITL's least-privilege tool allow-list (escalation.create only) and its A2A comms contract — subscribing to the classifier, safety-override and routing announcements, publishing the review decision for Reflection to consume.
  • Built ClinicianHandoffAgent: a bounded, faithfulness-first summariser that turns the fully-assembled case into a plain-language handoff note, grounded in retrieved citations only when a safety rule actually fired, with a deterministic template fallback that can't invent facts the LLM path could.
  • Before → after: HITL started as a two-outcome policy node (escalate / don't). After the widening in Decision 1 below, it's a three-outcome gate (escalate / ask the patient one clarifying question / proceed) — the same floors as before, now with a way to resolve low confidence without automatically consuming a clinician's time.

Key design decisions

Extending HITL into a true agentic component ◆ interactive demo below

Context

Professor Junhua flagged that the original HITL implementation didn't qualify as a true agentic component within the system's architecture.

Alternatives considered

Rewriting HITL as an LLM-based agent was on the table implicitly — it's the obvious way to manufacture "reasoning." We rejected it as a team: the project's own audit is explicit that the fix for a flagged policy node is never "make it call a model" — redflags.py's deterministic rules are intentionally not LLM-based because they're the last line of defense, and turning the last gate before a clinician into a probabilistic one would trade a guarantee for a guess. The other option was doing nothing beyond a written justification for why HITL is fine as a two-outcome policy node — rejected because it left the clarifying-question evaluation (E2) permanently blocked with no path to actually asking a patient anything.

Chose

Widened HITL's action space to three outcomes — escalate / ask the patient one clarifying question / proceed — reading a clarifying-question proposal the Severity-Classifier already computes and was publishing to my agent's inbox unread. The three original floor rules (safety trigger, low confidence, cross-visit recurrence) stay untouched as a hard floor asking can never override.

What did this cost me? click to reveal

The gain threshold that decides whether asking beats escalating (1.0, a triage-workload judgement, not a modelling one) was mine to set with no ground truth to validate it against — I inherited it as an unvalidated number from a teammate's prototype and own defending it. And the widening only closes half the loop: HITL can now decide to ask, but nothing downstream can yet surface the question to a patient or resume the case with an answer — that gap is scoped out in a handoff note for the platform owner. HITL also still classifies as a policy_node, not a genuine agent, under the project's own capability test: the choice between three outcomes is still a threshold on a number a peer computed, not inference I perform.

Retrieval as a Python branch, not a model-driven tool call

Context

My original design note for the Clinician-Handoff agent called it "ReAct-style: decide what's relevant, optionally retrieve grounding context via RAG, then generate." Once I actually built it, the project's LLM layer (llm.py) turned out to expose only a single-shot complete() across its provider chain (Claude CLI → OpenAI → optional self-hosted Ollama) — there's no function-calling loop for a model to request a retrieval mid-generation the way a true ReAct agent would.

Alternatives considered

Building a genuine multi-step tool-calling loop around the provider chain — more faithful to "ReAct" on paper, but would have meant hand-rolling a calling protocol the underlying providers don't uniformly support, for one retrieval decision that has an obvious deterministic answer anyway. The other option was retrieving unconditionally on every escalation for a veneer of "the agent used RAG" — rejected because it grounds cases that have nothing in the rule table to cite, padding the summary with irrelevant citations.

Chose

Made the retrieval decision itself a plain Python branch (_should_ground): ground only when a safety-override rule actually fired, since that's the only case with something concrete in redflags.py to cite. Retrieved citations are then handed to the LLM as fixed context it must stay inside, not as something it can request more of — mirroring the pattern the Severity-Classifier already uses for its own RAG calls.

What did this cost me? click to reveal

I gave up the ability to call this "real" agentic tool use — it's an honest downgrade from the original design note, not the ReAct pattern I'd originally scoped. What it buys back is the safety property that actually matters here: since the model can never request its own retrieval, a prompt injection in the patient's words has no channel to fetch or fabricate grounding it wasn't given — faithfulness stays a property of the Python branch, not of the model's good behaviour.

Outcome & reflection

The escalate/ask/proceed widening shipped fully unit-tested against seven acceptance cases (low-confidence-with-a-good-proposal asks; a safety trigger, P1/P2 acuity, or a repeat clarification all still escalate; a run with no message bus at all is byte-identical to pre-widening behaviour). The handoff agent passed the same bar plus a faithfulness-specific eval (E7) scored against its real LLM path, not just the deterministic fallback. My own escalation policy also earned its keep before either of those: the project's HITL evaluation (E5) initially gated on red-flag recall alone, which I flagged as a weak test — recall is trivially maximised by escalating everything — and pushed for a must-NOT-escalate half with a specificity floor. That gate failed immediately (0.50 against a 0.80 bar) and caught a real blind spot: the severity model had zero features for minor trauma, so a bruise, a cut and a sprain all collapsed to the same confidence score as a genuine unknown and flooded my own gate.

Neither agent is wired into the live pipeline yet — by team convention each of the five of us works in isolation on our own agent file and merges independently, so both land as fully-tested code plus a written integration handoff note (the ask/resume API gap for HITL; the six-file diff and ordering constraint — after Reflection, not after HITL — for Clinician-Handoff) rather than a live merge. With more time I'd close that loop myself: wire the patient-facing resume path so a clarifying question can actually reach someone, and read ground_truth.jsonl back into HITL as memory, which is the one upgrade that would make the gate reason from how clinicians have actually ruled on similar cases instead of a fixed threshold — the difference between a policy node and the genuine agent this component is still honestly not.
