DAY 2 · 19 AUG

Grounding the model in things it can't guess

--notes-file: your own notes outrank the transcript

cebece5

Your own rough notes now win when they disagree with the transcript.

▸ Why it mattered

A raw transcript is often ambiguous even to a careful human reader — the notes act as ground truth.

Confirmed in testing A short notes file surfaced an action-item owner with zero recognizable mention anywhere in the Whisper transcript, and recovered several items a transcript-only run had missed.

Speaker diarization, solved by not guessing

a649170

Craig's per-speaker tracks replace diarization guesswork — attribution by construction, not inference.

▸ Why it mattered

Whisper has no concept of who's talking on a mixed-down file. Each track is transcribed independently, then merged chronologically.

Confirmed in testing Most of any one track is silence. Built-in no_speech_prob alone missed background noise that produced fabricated text — measured avg_logprob ≈ −4.8 on real garbage output vs. −0.6 to −0.9 for genuine speech. Now filters on both.

Verify the name-map once, then reuse it

078c690

Usernames get relabeled to real names before summarization, not left for the model to resolve mid-sentence.

▸ Why it mattered
Confirmed in testing Whisper consistently misheard "Heriz" as "Harris" throughout a real transcript. Relabeling first measurably improved attribution over passing --participants alone.

Three passes to stop content going missing

8afdb22

One-pass summarizing quietly drops details — three passes catch it.

▸ How the verify pass catches what organize drops

On a real 30-minute, 5-person transcript, organize alone dropped a decision and an action item — both present in the extract step, despite "never drop a bullet" instructions. Verify diffs against the raw extraction and backfills what's missing.

DAY 3 (LATE) · 20–21 AUG

One real run, one real speaker shown as two people

acc9545

"Madooshik95" and "Aaron" — same person — showed up as two people in the notes.

▸ Root cause & fix
Real bug, real run Without CRAIG_NAME_MAP set, the transcript kept raw Discord usernames. Fix: run_pipeline() now also derives --participants from the same map automatically — relabeling alone wasn't enough; all three grounding levers together (relabeled transcript + --participants + --notes-file) were what testing had already shown worked best.

Notes that aren't the same file every time

bba1201

A static notes file forced an .env edit and restart per meeting. Now it's an optional attachment on the command itself.

"I don't see the new option" — an hour-long red herring

b117ae2

The new parameter was real and registered — just not visible yet.

▸ Root cause
Root cause Global command sync can take Discord up to an hour to propagate. Added optional DISCORD_GUILD_ID for guild-scoped sync, which is instant — with a printed warning if left unset.

A progress bar driven by real signals, not a spinner

5970535

A silent multi-minute wait became a real, data-driven progress bar.

▸ How
Confirmed in testing Reads Craig's real job-status transitions (starting → encoding → finalizing → complete) and parses pipeline.py's actual stdout ("Transcribing track X/Y", "Pass X/3"), weighted 90/10 transcription/ summarization to match real observed timing. One Discord message is edited in place, throttled against rate limits.

Reflection

What I'd tell someone reading the commits

Honestly, the Craig dead-end stung more than it should have — I'd read the source carefully, it looked authoritative, and being wrong about something I'd double-checked took longer to let go of than the actual fix did. Three things I noticed about my own process, looking back:

Evidence over intuition

"base should be fine" and "the repo says /api/recording/:id" both sounded reasonable and were both wrong until tested for real. Slow and right beats fast and plausible.

Ground truth over inference

Per-speaker tracks over diarization guesswork; a human's own notes outranking the transcript. Reach for a known fact before a smarter guess.

Tradeoffs named, not hidden

Three-pass costs 3× the API calls. Multitrack costs N× the runtime. Every shortcut is a written-down choice, not a hidden default.

If I rebuilt this today: I'd make the diarization filtering thresholds config instead of hardcoded constants the first time — avg_logprob was hand-tuned against one real recording, and won't generalize to a noisier room without re-tuning by hand again.

Status

Where it stands, 1 Sep 2026

  1. The full loop is dogfooded, not just built — real meetings have found six real bugs since launch: four the first night (duplicate speakers, static notes, an invisible new option, a silent wait) and, eleven days later, an Action Item coverage gap that a fix improved but didn't fully close.
  2. Every fix so far has landed as a config/UX/prompt gap, not a broken core mechanism — and the last one was honest enough to say it wasn't complete rather than call it solved.
  3. Multi-speaker overlap on a single mixed-down file is still unsolved — out of scope for this MVP, would need a dedicated diarization step.
